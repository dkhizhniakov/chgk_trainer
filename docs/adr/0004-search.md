# ADR-0004: Поэтапная стратегия поиска

**Статус**: принято

## Контекст

Пользователю нужен поиск по тексту вопросов/ответов и по базе знаний, а также произвольные комбинации фильтров в таблицах. DynamoDB поддерживает только запросы по ключам и индексам.

## Решение

1. **MVP**: фильтры по GSI и индекс-элементам (`IDX#TAG#…`, `IDX#YEAR#…`), дополнительная фильтрация в Go; префиксный поиск сущностей по нормализованному имени (`GSI2`).
2. **Встроенный индекс**: [Bleve](https://github.com/blevesearch/bleve) с русским анализатором внутри Go-сервиса. Индекс строится CLI-командой из DynamoDB, сохраняется в S3; задача ECS скачивает его при старте и обновляет по DynamoDB Streams (через короткий poller или Lambda → SQS). Возможен благодаря постоянному процессу (ADR-0002).
3. **OpenSearch Serverless** — только если объём/нагрузка перерастут встроенный индекс (минимальная стоимость заметно выше всего остального стека).

## Последствия

- (+) Нулевые затраты на поиск на старте.
- (−) В MVP ограниченные комбинации фильтров в таблице вопросов.
- (−) Этап 2 требует синхронизации индекса между несколькими задачами ECS.
