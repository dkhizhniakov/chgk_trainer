# ADR-0001: Монорепозиторий и OpenAPI как контракт

**Статус**: принято

## Контекст

Один разработчик, три части (frontend, backend, infra), которые меняются согласованно. Нужна типобезопасность на границе React ↔ Go.

## Решение

- Один репозиторий: `api/`, `backend/`, `frontend/`, `infra/`, `scripts/`, `docs/`.
- `api/openapi.yaml` — единственный источник истины для API. Go-сервер (oapi-codegen, strict server) и TS-типы (openapi-typescript) генерируются из него.
- Сгенерированный код коммитится (сборка не зависит от генераторов), CI проверяет, что он актуален.

## Последствия

- (+) Изменение API в одном PR вместе с реализацией и UI; рассинхронизация ловится компилятором.
- (+) Спецификация служит документацией API.
- (−) Нужно поддерживать YAML-спецификацию вручную (дисциплина «сначала спека»).
